## Implementation and verification lanes

1. Transport safety (`plugin/src/bridge.rs`, client pending lifecycle): reproduce unsafe fallback and waiter leaks, implement dispatch-aware errors and bounded cleanup, prove no replay after dispatch.
2. Legacy handlers (`plugin/src/handlers.rs`): reproduce timeout/verification false success, targeted fill and monitor issues; fix at tool boundaries, preserving ordinary JSON data.
3. Shared contract (`crates/client/src/workflow/`, `outcome.rs`, `batch.rs`): test strict schema, expression slots/pointers, bounded validation and outcomes; implement; test report persistence failures separately from execution.
4. DOM execution (`plugin/src/workflow/page.js`, `dom.rs`): test exact scope/entity intersection, controlled input events, actionability, page identity and bounded observers before integrating into the service.
5. Journal (`plugin/src/workflow/journal.rs`): test exclusive ownership, bounded durable acknowledgements, corrupt tails, fingerprints and interrupted recovery without replay.
6. Service and arbitration (`plugin/src/workflow/`, state/setup): test atomic deduplication/CAS/cancel/deadlines, safe continuation and reconciliation; implement shared leases and quarantine, bounded redacted evidence and reports.
7. Adapters (CLI, WS, embedded/standalone MCP): test schemas/parity and failure exit semantics; use raw internal results; forward workflow calls to the application service.
8. Integrate an isolated Tauri fixture and executable example. Verify actual UI behavior on the available macOS host, distinguish portable unit coverage from untested platforms, and record request/dispatch/effect counts.
9. Update design/status/migration documents and shipped skill/reference copies. Review spec acceptance rows against evidence and close implementation gaps.

## Required checks

Run targeted regression tests for each lane before and after implementation. Final integration: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -p connector-cli -p connector-mcp-server -p connector-client`, `cargo test -p tauri-plugin-connector`, `cargo check -p tauri-plugin-connector --no-default-features`, JavaScript tests and isolated live fixture checks. Record exact failures or unavailable platforms in `docs/workflow-implementation-status.md`.

## Completion boundary

No automatic retry of possibly dispatched writes. No unverified success, arbitrary workflow code, automatic restart replay, or P3 capability claims. The final report must distinguish execution, verification, side effects and evidence coverage; all supported public capabilities require executable coverage. Keep the goal active until all required implementation and feasible checks are complete.
