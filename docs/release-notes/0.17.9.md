# 0.17.9

## Fixes

- **Locked-screen screenshots fail promptly on macOS.** Default/legacy, auto, webview_native, window_native and DOM captures return primary `screen_locked` before any page/runtime probe, native capture or optional bring-to-front. A lock arriving during a read-only capture cancels the wait and discards its pixels instead of waiting for a generic timeout or returning a solid image. Default CLI capture no longer retries a known lock through the legacy renderer.
- **Eval names the real cause first.** Known locked sessions refuse before dispatch and before background liveness probing. The first message is `screen_locked` with an unlock remedy, never “rerun with --bring-to-front”. Already-dispatched writes keep their uncertain-outcome semantics.
- **Focused registry upgrade guidance.** Doctor/status and the upgrade guide use `cargo update -p tauri-plugin-connector -p connector-client --precise 0.17.9`: two package selectors, one shared version selector. Cargo 1.99.1 rejects repeated `--precise`. An isolated 0.17.7 → 0.17.8 consumer probe changed only these two packages while preserving deliberately old `cc` and `mime`; evidence is in `docs/upgrade-evidence/0.17.9-focused-update.json`. Git dependencies keep the command without `--precise`. Review lockfile diffs: new requirements can still need transitive changes.
- **Doctor explains the capability failure.** A missing `connector:default` remains ✗ / exit 1. The detail explains why WS/eval/screenshot can work while frontend-to-Rust push commands fail, naming all affected commands.

These are functional fixes for the debug-only connector; no consumer application or git-strata port policy changes are included.

## Install / upgrade

```bash
brew update && brew upgrade tauri-connector
# or
cargo install connector-cli --version 0.17.9 --locked

# crates.io app (raise the manifest requirement first if pinned older):
cargo update --manifest-path src-tauri/Cargo.toml -p tauri-plugin-connector -p connector-client --precise 0.17.9
# git-main app: same command without --precise 0.17.9

npx skills add dickwu/tauri-connector
```

Rebuild and restart the host app; upgrading the CLI alone cannot replace an embedded plugin. Preserve existing fixed ports and feature gates.

## Verification note

Locked-screen regressions inject native lock state; the user's MacBook is never locked for testing. The desktop was already locked when live verification ran against a separate, background-only local fixture (no production backend): identity and embedded MCP initialize reported 0.17.9, and all screenshot paths refused with primary `screen_locked` in 8–20 ms. Eval returned the same primary error in 8 ms (827 ms with the CLI's native focus step); snapshot refused in 16 ms. No screenshot file was produced; the fixture was stopped. Evidence: `docs/upgrade-evidence/0.17.9-locked-live.json`. Unlocked pixel-capture verification was not performed locally because the desktop remained locked; cross-platform native smoke remains a required CI gate.
