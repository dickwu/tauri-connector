# v0.17.8

This patch release fixes the functional bugs reported by the apps that retested 0.17.7: async `eval` values, permission-denied quarantines, scrolling, startup races, locked screens, window focus, hidden snapshots, failed starts, `doctor`, discovery of bundles outside `target/`, screenshot output and port swapping between apps. Unknown-outcome quarantine still never replays a dispatched write.

## Bug fixes

- **Async `eval` returns the value of a trailing block.** `eval 'await x(); if (ok) { "a" } else { "b" }'` (and a trailing `try`/`catch`/`finally` or nested block) now returns the same completion value as a synchronous script, not `null`. Loop bodies are never rewritten, and each statement still runs once.
- **A Tauri permission denial is effect-free.** An `eval` stopped by a Tauri ACL refusal (`<command> not allowed ...`, `Command <name> not found`) reports `effect: none` and no longer quarantines the window.
- **Quarantines expire.** A quarantine set by an uncertain write expires 60 s after it was set (checked on the next acquire or `resources` listing). The `resource_busy` message says how long is left, and `resources` shows when each entry expires. Releasing early with `resources release` still works.
- **`scroll` moves the container a user would scroll.** With `--selector`, that element or its nearest scrollable ancestor; without it, the container under the viewport centre, then the focused or hovered element's, then the document. The result reports `container`, `source` and `scrolledBy`. The CLI and the MCP tool share one implementation.
- **Commands fail fast before a webview connects.** With no bridge client connected the refusal (`bridge_not_connected`) now comes after about 3 s instead of at the request deadline. A window label that does not exist yet fails at once with `window_not_ready`. Both are `dispatched: false`, retryable and quarantine nothing.
- **A locked screen is named.** On macOS, `status` and `runtime-health` report `screenLocked`. While the screen is locked, refusals that would say `window_not_visible` / `bridge_not_connected` use `screen_locked`, `runtime-health` concludes `screen_locked`, and request timeouts append a note. The app is throttled, not dead.
- **`windows focus` brings the window in front on macOS.** It activates the app and orders the window front, retrying once if the window did not take focus within 400 ms.
- **A hidden window's snapshot is refused every time.** A `snapshot` of a minimized or natively hidden window fails at once with `window_not_visible`, every time and without probing the page, instead of only when the page happened not to answer.
- **A failed connector start is recorded.** When the connector cannot start (for example a busy exact port), the PID file carries `startup_error`. `status` lists the app as `failed` with the reason, and commands say `its connector did not start` instead of attaching to whichever app holds the port. A live PID file of another running connector is never overwritten.
- **`doctor` fails when it should.** A running app whose connector did not start, and an explicit `--pid-file` that cannot be read, are failures (exit 1) rather than reasons to probe the default ports. `--json` adds a top-level `fixes` array.
- **Plugin update hints work for git dependencies.** `status` and `doctor` suggest `cargo update -p tauri-plugin-connector -p connector-client` (with the app's manifest path) for crates.io and git sources alike, and no longer suggest `--precise`.
- **Packaged apps outside `target/` are found.** A bundle started with `open` writes its PID file to `<app data>/<identifier>/.tauri-connector/.connector.json`; discovery and `doctor` now read those records (`TAURI_CONNECTOR_APP_DATA_ROOT` overrides the root). An app that answers `unauthorized` is reported as such instead of being skipped, and `app_not_found` lists what was checked.
- **One screenshot artifact shape.** `screenshot --bring-to-front` (and `--source` / `--target`) prints the same 25-key `artifact` object as the default capture: `artifactId` / `id` are `shot_<file stem>`, and `protectedArtifactId` holds the plugin's protected id. Those captures are now recorded in the artifact manifest too.
- **Apps on the default port ranges stop swapping ports.** Each app first retries the WebSocket and MCP ports it bound last time (`<app data>/<identifier>/.tauri-connector/ports.json`), then scans the range. A single app keeps 9555/9556; two apps keep their own ports after their first run together, whichever starts first. Exact ports still win. `TAURI_CONNECTOR_REMEMBER_PORTS=0` turns it off. The internal bridge port is not remembered.

## Dependencies

- Cargo (root and `examples/workflow-fixture/`): async-executor 1.14.1, async-lock 3.5.0, cc 1.11.0, crc32fast 1.5.4, jiff 0.2.39, js-sys / web-sys 0.3.107, log 0.4.35, utf8_iter 1.1.0, wasm-bindgen 0.2.130, wasm-bindgen-futures 0.4.80, zcheapstr 1.2.0.
- npm: `ws` 8.22.0 → 8.22.1 (`cli/` and `server/`). Every other npm dependency and GitHub Action was already at its latest version.
- Not updated: `cairo-rs` / `gio` stay at 0.18 (latest 0.22) to match the gtk-rs 0.18 stack used by webkit2gtk/wry. `generic-array` 0.14.7, `matchit` 0.8.4 and `toml` 0.8.2 (with `toml_datetime` / `toml_edit`) are held by exact pins in upstream crates. CI stays on Node 22, per `engines`.

## Known limitations

- An explicit screenshot output path that already exists still fails with `output_exists` under `--bring-to-front` / `--source` / `--target`, while the default capture saves a unique name. Pass `--overwrite` or a new path.
- `screen_locked` detection is macOS-only; elsewhere `screenLocked` is `null`.

## Install

```sh
brew update && brew upgrade tauri-connector
# Or install the command-line packages directly:
cargo install connector-cli --version 0.17.8 --locked
cargo install connector-mcp-server --version 0.17.8 --locked
```

Apps: `cargo update -p tauri-plugin-connector -p connector-client` (crates.io `"0.17"` specs pick up 0.17.8; git dependencies move to the latest `main`).
