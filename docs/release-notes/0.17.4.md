# v0.17.4

This patch release fixes what git-strata and the R2 retest of 0.17.3 turned up: strict-CSP apps, background windows, Overlay title bars, reload timing and a set of CLI rough edges. Unknown-outcome quarantine and the rule against replaying dispatched writes are unchanged.

## New

- **Bring a background window to the front natively.** A minimized, hidden, covered or other-Space window stops rendering frames, so webview calls time out (`capture_not_ready: render_frame_timeout`, `WS bridge timeout`). Three opt-in ways to fix that without a webview round trip:
  - `tauri-connector windows focus [--window-id <id>]` unhides the app (macOS), unminimizes, shows and focuses the window and prints `{windowId, focused, visible, minimized, focusError}`.
  - MCP `manage_window(action: "focus")`, in the embedded server, the standalone `tauri-connector-mcp` and the Bun/TS server.
  - `--bring-to-front` on `eval`, `wait` and `screenshot` (MCP screenshot: `bringToFront: true`).
  - Window list, info and focus never take a resource lease, so `windows focus` works while a window is quarantined after a timed-out eval.
  - A locked or sleeping screen still renders nothing until it is unlocked; the first call after focusing can need one retry while the window comes up.
- **Clear errors for hidden pages.** A capture of a hidden page fails with `window_not_visible`, naming the cause and `windows focus` / `--bring-to-front`, instead of a blank or stale image. A frame timeout on a page that does not report itself hidden, and an eval or wait that gets no answer, now carry the same hint.

## Bug fixes

- **Strict CSP apps work.** When the page CSP blocks `eval`, bridge commands are delivered as native script instead, and an eval refused by CSP is named as such rather than timing out.
- **`eval --timeout` fires at the requested deadline.**
- **Screenshots.**
  - The default `screenshot` goes through the protected capture pipeline (same image and size as `--source auto` and MCP), keeping the legacy `path`/`sha256`/`width`/`height`/`artifact` fields. It falls back to the legacy renderer only when the pipeline is unavailable.
  - Native captures are sized to the CSS viewport, so an Overlay title bar no longer adds a band or breaks the size check.
  - Right after a (hot) reload the capture waits for the new page runtime and a settled viewport instead of failing, capturing an old frame or reading a transient 1920px width. Results report `consistency.viewportSettled`.
  - A missing snapdom renderer is an effect-free `capture_backend_unavailable`.
  - An existing export path names `--overwrite`, and exported files keep default permissions.
- **Snapshots and locators.** Explicit snapshot refs survive the DOM auto-push, so `fill @eN` keeps working, and `locator --name` works without `--role`.
- **IPC.** A Tauri ACL refusal of `ipc exec` is effect-free instead of quarantining.
- **CLI.**
  - `doctor --json` prints only JSON, optional checks (withGlobalTauri, snapdom) warn instead of failing, and capability patterns from `build.rs` are honoured.
  - `status` lists apps found by port scan.
  - `wait --function` is accepted as an alias of `--fn`.
- **Logs.** Client connect/disconnect lines only appear with `TAURI_CONNECTOR_VERBOSE`. Each launch starts a fresh log and keeps the previous run as `.prev.log`.

## Skill

- Documents `windows focus`, `manage_window` focus, `--bring-to-front`, the default capture pipeline, what `webview_native` does not show (backdrop-filter, title bar, vibrancy), hidden windows, capturing right after a reload and the fresh log files.

## Install

```sh
brew upgrade tauri-connector
# Or install the command-line packages directly:
cargo install connector-cli --version 0.17.4 --locked
cargo install connector-mcp-server --version 0.17.4 --locked
```

Host applications on `tauri-plugin-connector = "0.17"` pick up the fixes with `cargo update -p tauri-plugin-connector`, then a rebuild and restart of the app. `windows focus` and `manage_window` focus need the 0.17.4 plugin in the app; older plugins answer with an unknown-command error and the CLI says so.
