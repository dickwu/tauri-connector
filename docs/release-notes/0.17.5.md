# v0.17.5

This patch release fixes what the R2, Inter and git-strata retests of 0.17.4 turned up, and names each app's project so apps sharing the default ports can be told apart. Unknown-outcome quarantine and the rule against replaying dispatched writes are unchanged.

## Bug fixes

- **A stale PID file no longer attaches you to a different app.** When the nearby `.connector.json` names a process that has exited, or its port now answers as another process, the CLI and the standalone `tauri-connector-mcp` used to fall back to a port scan and silently attach to whatever single app was running (for R2, GFIT Workout on 9555). They now fail with `stale_pid_file`, naming the stale record and the apps the scan found, and how to proceed. A scanned app with the record's own app id is still used. To attach to an unrelated app anyway, pass `--app-id`/`--port`, or opt in with `--any-app` (`TAURI_CONNECTOR_ANY_APP=1`, which the standalone MCP server also reads).
- **One screenshot output shape.** The default `screenshot` and `--source <source>` now print the same fields: `path` and `exportedPath`, `sha256`, `width`, `height`, `sizeKb`, `warnings`, plus the capture report (`artifactId`, `storage`, `retainedUntil`, `captureSource`, `viewport`, `geometry` and so on). The nested `artifact` object stays on the default capture for existing scripts. Captures also report `sourceSelection` (`requested`, `order`, `selected`, `reason`), which says why `auto` picked its source.

- **No more wry URL panic.** Reading a WebView's URL could abort the app inside wry (`url_from_webview` unwrapping a nil URL while a page was being created or torn down). The plugin now reads the URL without that unwrap and treats a missing URL as unknown.
- **The native fallback screenshot is cropped to the viewport, or says it isn't.** The legacy whole-window (xcap) fallback strips the window decorations and the macOS title bar when the page's CSS viewport proves where it is. The result carries `viewportCrop` (`basis`: `css_viewport`, `client_area` or `uncropped`, plus `rectPx` and `windowPx`), and anything short of `css_viewport` adds a `viewport_crop_unverified` warning that states whether the image was cropped at all. The uncropped case happens when protected capture times out while the page is still loading, because the page cannot report its viewport yet; once the page has loaded the capture is cropped (Inter: 3840x2036 at DPR 2 for a 1920x1018 viewport).
- **Commands wait out page reloads instead of answering from the old page (git-strata #8).** A script that reaches a document that is unloading, still parsing, or missing the bridge helper it calls now refuses before it starts (`connector_not_run: page_navigating`, `page_loading` or `helper_missing`). The host re-injects a missing bridge and retries such refusals within the command's deadline, since nothing ran, and never retries a script that started. When the page stays unready it reports a clear not-dispatched error.
- **Console output from document start.** A document-start script buffers `console.*` calls made before the bridge connects, and the bridge drains them into the log, so early startup errors are no longer lost.
- **Quieter, accurate doctor warnings.** `Runtime app.add_capability not detected` no longer fires when a build script generates the capability or a capability file already grants `connector:default`. The stale skill copy warning (for example under `~/.codex/skills`) is reported once per real directory, not once per symlink to it.

## New

- **Project names for every instance.** Several apps (R2, GFIT Workout, Hub, git-strata-gui) share ports 9555/9556. A 0.17.5 plugin reports `projectName`, `projectRoot` and `cargoPackage` in `identity` and in `.connector.json`. The name is `ConnectorBuilder::project_name(..)` when set, else `productName`, else the Cargo package, else the directory name. `status` and `status --json` show `project=` for every instance, including apps found by port scan (it now lists every verified app on 9555–9655, even when it cannot pick one). `--project <name>` (or `TAURI_CONNECTOR_PROJECT`) selects by project name, Cargo package, app name, app id or root, and fails with `project_mismatch` when no running app matches. A command run inside a Tauri project refuses the only running app when it belongs to a different project root (override with `--project`, `--port` or `--any-app`). The standalone `tauri-connector-mcp --project <name>` serves only that project, reports it in `initialize` `_meta["dev.tauri-connector/project"]` and logs it. doctor fails when `.mcp.json` points at another project's MCP port, including another checkout of the same app. Older plugins show `unknown project` and are never refused for it.

- **Plugin version and app name in identity.** `identity` (MCP `app_identity`) returns `pluginVersion`, `appName` and `appVersion`, and `status` shows `plugin=<version>` for every instance plus the connected app's name, id and plugin version. When nothing connects, `status` prints the discovery error (`resolveError` in `--json`). Plugins older than 0.17.5 show `plugin=<0.17.5 (unreported)`, and `identity` adds a `pluginVersionNote`.
- **doctor checks who owns the `.mcp.json` port.** It fails when the MCP server on that port reports a different app than `tauri.conf.json` `identifier`, or when the project's live PID file says the app serves MCP on another port, and prints the correct URL. The embedded MCP `initialize` result now names its app in `_meta["dev.tauri-connector/app"]` (left out when the host sets a workflow token).
- **doctor flags the legacy SSE transport.** A `.mcp.json` entry with `"type": "sse"` (or `"transport": "sse"`, or an `/sse` URL) warns, with the exact `{ "type": "http", "url": "http://127.0.0.1:<port>/mcp" }` replacement.

## Known limitations

- `webview_native` captures still do not render compositor-only effects such as `backdrop-filter`; use `--source window_native` for the composited pixels.

## Install

```sh
brew upgrade tauri-connector
# Or install the command-line packages directly:
cargo install connector-cli --version 0.17.5 --locked
cargo install connector-mcp-server --version 0.17.5 --locked
```

Host applications on `tauri-plugin-connector = "0.17"` pick up the fixes with `cargo update -p tauri-plugin-connector`, then a rebuild and restart of the app. The stale PID file refusal and the SSE check are client-side and work with any plugin. The reload handling, early console capture, viewport crop, URL panic fix, project names and the plugin version, app name and `.mcp.json` ownership check by app id or project need the 0.17.5 plugin in the app; with older plugins doctor falls back to comparing the PID file port.
