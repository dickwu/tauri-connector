# v0.17.0

This release fixes functional bugs across the plugin, CLI, and standalone MCP server, and moves to the latest dependency releases. It adds no new tools. Workflow deduplication, unknown-outcome quarantine, and the rule against replaying dispatched writes are unchanged.

## Bug fixes

- **Safe script injection.** Selectors, text, regex patterns, style property names, and event names are now encoded as JavaScript string literals before they are injected, so quotes and backslashes no longer break `find`, `get_styles`, snapshots, drag, fill, type, or IPC event listeners.
- **Drag strategies are validated up front.** `dragStrategy` and the CLI `--strategy` flag only accept `auto`, `pointer`, or `html5dnd`. Any other value is rejected as `invalid_arguments` before dispatch, so it no longer quarantines application resources. `steps` is clamped to at least 1.
- **The standalone MCP server starts without a running app.** `tauri-connector-mcp` finds the app on the first tool call and reconnects if it restarts. It keeps answering `initialize`, `tools/list`, and `ping` while tool calls run, runs tool calls concurrently, honors `notifications/cancelled`, and finishes in-flight calls before exiting at end of input.
- **No more port races.** The bridge, WebSocket, and MCP HTTP listeners keep the socket they bind instead of probing a port and binding it again later.
- **Port ranges include their end.** `port_range(start, end)` and `mcp_port_range(start, end)` now include `end`, and `start > end` is rejected. If you set a single port as `(p, p + 1)`, change it to `(p, p)`.
- **Legacy SSE transport follows the spec.** `POST /message` returns `202 Accepted` with an empty body and delivers the JSON-RPC response only over the SSE stream, so responses are no longer duplicated. Unknown or closed sessions get `404`. Legacy sessions are removed when their stream closes.
- **MCP sessions no longer leak.** Streamable HTTP sessions that have been idle for one hour are pruned.
- **`.connector.json` moved and is cleaned up.** The PID file is written to the nearest `target/` directory above the executable, falling back to the app log directory, so it never lands inside an app bundle. It is removed on normal exit if it still belongs to the exiting process.

## Docs

- The documented port defaults and ranges are corrected. `TAURI_CONNECTOR_PORT` is documented as a client-side override only; it does not change the port the plugin listens on.

## Dependencies

- Updated all Rust and npm dependencies to their latest compatible releases. These include tauri 2.12 and wry 0.57.
- On Windows, the native screenshot backend moves to `webview2-com` 0.39 and `windows` 0.62 to match wry.
- On Linux, `gio` and `cairo-rs` stay on 0.18 to match `webkit2gtk` 2.0 and gtk 0.18 used by Tauri 2.
- Removed the unused `tauri-plugin` runtime dependency; it remains a build dependency.

## Install

```sh
brew upgrade tauri-connector
# Or install the command-line packages directly:
cargo install connector-cli --version 0.17.0 --locked
cargo install connector-mcp-server --version 0.17.0 --locked
```

Update the host application's optional `tauri-plugin-connector` dependency to `0.17`, keeping its existing development feature gate. Installing a CLI alone does not update or restart other applications' embedded plugins.
