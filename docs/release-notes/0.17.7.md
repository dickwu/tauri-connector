# v0.17.7

This patch release fixes what the 0.17.6 retests turned up in screenshots, read-only commands, background windows, async `eval` and `doctor`. It also adds exact, fail-hard ports. Unknown-outcome quarantine and the rule against replaying dispatched scripts are unchanged.

## Bug fixes

- **Screenshots during navigation wait instead of failing.** A capture that meets a navigating document waits for the navigation to finish, within the request's deadline. If the page is still navigating at the deadline, it fails with `page_navigating` and `retryableBeforeDispatch: true`. It no longer fails with `not_dispatched: Target document is navigating`.
- **A screenshot queued behind a long `eval` reports `resource_busy`.** After the 15 s lease queue wait, the error is `resource_busy`. It is no longer `capture_timeout` followed by a legacy-renderer fallback. The client's transport timeout now covers the queue wait plus the capture.
- **Read-only commands never quarantine.** `get url` / `get title` / `get count` / properties, plus MCP `webview_execute_js` with `readOnly: true`, report `effect: none`. When no webview bridge client is connected and the eval channel does not answer, they fail with `bridge_not_connected` (`dispatched: false`, `retryableBeforeDispatch: true`) instead of `outcome_unknown`.
- **Hidden-window snapshots match `eval`.** A snapshot of a minimized, hidden or covered window fails with `window_not_visible`, `dispatched: false`, retryable. It no longer reports `outcome_unknown`.
- **`window_not_visible` names the fix.** The message points at `--bring-to-front` (`eval`, `wait`, `screenshot`) and `tauri-connector windows focus`, or MCP `manage_window action=focus`.
- **`screenshot --output-dir DIR --name-hint X` saves into `DIR`.** This also applies with `--source`, `--target` and `--bring-to-front`, and the directory is created when missing.
- **Export errors are JSON.** An existing output file without `--overwrite` fails before capture with `{"code":"output_exists","stage":"export","path":...}` and a non-zero exit. Other write failures use the same shape (`export_failed` / `export_refused`).
- **Async `eval` returns its last expression.** `eval 'await load(); document.title'` prints the title, not `null`. Scripts with an explicit `return` are unchanged. Under a page CSP that blocks `unsafe-eval`, add the `return` yourself.
- **`doctor` uses the ports the app bound.** The `.mcp.json` fix lines and the runtime MCP probe use the MCP port from `.connector.json`, then `TAURI_CONNECTOR_MCP_PORT`, then 9556. The "no webview bridge clients" fix names the bridge port from `.connector.json` or the effective `TAURI_CONNECTOR_BRIDGE_PORT` / `_BRIDGE_PORT_RANGE` (default 9300-9400). `doctor` now honours the global `--pid-file`.
- **Port docs agree.** SKILL.md, SETUP.md, README and the CLI reference now describe the same `TAURI_CONNECTOR_PORT` behaviour.

## New: exact ports

- `TAURI_CONNECTOR_PORT` (WebSocket), `TAURI_CONNECTOR_MCP_PORT` (MCP HTTP) and `TAURI_CONNECTOR_BRIDGE_PORT` (internal bridge), set in the app's environment, bind exactly that port. So do `ConnectorBuilder::port(..)`, `.mcp_port(..)` and `.bridge_port(..)`.
- A busy exact port is never skipped. The connector logs `port N set by TAURI_CONNECTOR_PORT is unavailable (...); an exact port never falls back to a range` and does not start. The host app keeps running. An invalid exact value also keeps the connector off.
- 0.17.6 read `TAURI_CONNECTOR_PORT` / `_MCP_PORT` as a start port for START..=START+100. Use `TAURI_CONNECTOR_PORT_RANGE` / `_MCP_PORT_RANGE` / `_BRIDGE_PORT_RANGE` (`START-END`) or `.port_range(..)` to scan a range.
- Precedence: builder exact > env exact > env range > builder range > default (9555-9655 / 9556-9656 / 9300-9400).
- `.connector.json` records the ports actually bound (`ws_port`, `mcp_port`, `bridge_port`).
- The CLI's `--port` defaults to `TAURI_CONNECTOR_PORT`.

## Dependencies

- npm: `@types/node` 26.6.5 → 26.6.6 (`cli/` and `server/`). Every other npm dependency was already at its latest version.
- Cargo: every lockfile (root, `plugin/`, `examples/workflow-fixture/`) was already at the latest compatible versions. `cargo update` changed only the workspace crates' own versions.
- Not updated: `cairo-rs` / `gio` stay at 0.18 (latest 0.22) because they must match the gtk-rs 0.18 stack used by webkit2gtk/wry. `generic-array` 0.14.7, `matchit` 0.8.4 and `toml` 0.8.2 (with `toml_datetime` / `toml_edit`) are held by exact pins in upstream crates (axum, tauri/system-deps, crypto crates). CI stays on Node 22, per `engines`.

## Known limitations

- `webview_native` captures still do not render compositor-only effects such as `backdrop-filter`. Use `--source window_native` for the composited pixels.
- `window_not_visible` is reported, not auto-fixed. Pass `--bring-to-front` to raise the window.

## Install

```sh
brew update && brew upgrade tauri-connector
# Or install the command-line packages directly:
cargo install connector-cli --version 0.17.7 --locked
cargo install connector-mcp-server --version 0.17.7 --locked
```

Apps: `cargo update -p tauri-plugin-connector -p connector-client` (crates.io `"0.17"` specs pick up 0.17.7).
